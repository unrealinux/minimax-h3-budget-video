# H3 提示词写法

H3 支持最长 7000 字符的提示词，这是它和早期视频模型最大的差别之一：**写得越具体，一次过片率越高，成本越低**。一次重跑就是一次全价，所以这里的每一段都直接对应钱。

## 六段式结构

按顺序写，每段一到三句。不要写成一段散文。

```
【主体】谁 / 什么，外观细节，服装与材质，年龄与状态
【动作】一个明确事件，从 A 到 B 的可见变化
【镜头】景别 + 运镜 + 焦段感 + 机位高度
【光线】光源方向 + 色温 + 时间 + 对比度
【声音】点名要什么声音（环境 / 拟音 / 对白 / 音乐）
【约束】不要出现什么，什么必须保持不变
```

### 为什么是这个顺序

模型对提示词的注意力不是均匀的。主体和动作决定它"生成什么"，镜头和光线决定"怎么拍"，声音和约束是修正项。把修正项写前面会稀释主体描述，这是过片率低的常见原因。

## 正例

**竖屏产品广告（5 秒，9:16）**

```
【主体】一瓶磨砂玻璃香水瓶，琥珀色液体，银色瓶盖，放在湿润的黑色石板上，
瓶身有细小水珠，标签是米白色烫金字。
【动作】镜头缓慢推近，瓶身表面的一颗水珠沿玻璃滑落到底部，
背景的水面出现一圈扩散的涟漪。
【镜头】中近景，微距质感，缓慢推近约 20%，机位与瓶身齐平，浅景深。
【光线】左后方单一暖光源，色温 3200K，右侧补冷光，高对比，暗部保留细节。
【声音】极轻的水滴声，低频环境嗡鸣，无音乐。
【约束】不要出现人手，不要出现文字叠加，瓶身形状全程不变形。
```

**人物口播（5 秒，16:9）**

```
【主体】35 岁亚洲女性，短发，米色针织衫，坐在靠窗的木桌前，
窗外是阴天的城市街景，桌上有半杯咖啡。
【动作】她抬头看向镜头，微笑，说一句短句，然后轻轻点头。
【镜头】中景，固定机位，85mm 人像焦段，轻微手持呼吸感。
【光线】窗户自然光从左侧来，柔和，色温 5600K，面部无明显阴影。
【声音】安静的房间底噪，她说中文，声音清晰靠前。
【约束】不要出现字幕，不要改变她的发型和服装，背景人物保持虚化。
```

## 反例与修法

| 反例 | 为什么失败 | 修法 |
|---|---|---|
| "一个电影感的城市夜景，很酷" | 没有主体、没有事件，模型自由发挥 | 指定一个具体事件："一辆出租车驶过积水路面，溅起水花" |
| "三个人同时穿过十字路口，各自打电话" | 多主体并发动作，H3 明确不擅长 | 拆成三个镜头，或改成"一个人穿过路口" |
| "镜头快速环绕，同时人物转身挥手" | 运镜与动作叠加，容易崩 | 二选一：要么环绕，要么转身 |
| "有脚步声" | 太笼统，容易没声音 | "皮鞋踩在湿水泥地上的脚步声，每步间隔约 0.5 秒" |
| "保持角色一致" | 抽象要求，模型无法执行 | 用 fl2v + 5 张参考图，把一致性交给输入而不是提示词 |

## 三种常见崩坏及修复

**1. 动作做到一半就停**
原因通常是动作跨度太大，5 秒装不下。修法：把动作压缩成"一个动作 + 一个结果"，或者延长到 8–10 秒。

**2. 画面后半段漂移（人脸变形、场景变化）**
这是长镜头的通病。修法：缩短到 5 秒；或用首尾帧把终点钉住；系列内容用参考图锁定形象。

**3. 没有声音 / 声音和画面对不上**
H3 的音效是跟着事件走的，但**低运动、安静的场景最容易生成静音**。修法：显式点名声音，并给出节奏（"每 2 秒一次"）。需要精准对白的，考虑 FLUX 3 Max。

## 提高过片率的四个习惯

1. **一次只写一个事件**。想要三段动作，就生成三条再剪。
2. **用具体名词代替形容词**。"米白色烫金标签"比"高级感标签"有效十倍。
3. **固定一套模板反复用**。同一条产品线用同一套六段式，改的只有动作和镜头，出片风格会自然统一。
4. **保留成功的 prompt 和 seed**。H3 的随机性不小，同一个 prompt 值得跑 2–3 次再判断好坏。

## 关于 H3-Context-IR

官方在服务端有一个 Context-IR 模块，负责把自由格式的多模态输入解析成结构化表示，并补全未指定的细节。它**没有开源**，只在 API 里生效。这意味着：

- 走官方 API / fal / Replicate 时，你写的中文长提示词会被它加工，效果通常比裸模型好。
- 自建 H3-Base 时没有这一层，同样的 prompt 出片质量会下降，需要自己重建预处理管线。

写 prompt 时可以利用这一点：**不必把所有细节都写死**，给 Context-IR 留出补全空间，但关键约束（不变形、不要字幕、人物特征）必须显式写。
